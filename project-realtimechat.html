06REALTIMECHAT / BACKEND PORTFOLIO

두 애플리케이션 인스턴스 사이에서도
대화가 이어지는 실시간 채팅.

Spring Boot와 React로 구현한 실시간 채팅 서비스입니다. HTTP Session 인증과 채팅방 권한 검증, MySQL 메시지 영속화, Redis Pub/Sub 기반 인스턴스 간 이벤트 전달을 연결했습니다. 기능 구현에서 끝내지 않고 EC2의 메모리 압박과 메시지 지연을 측정하며 운영 설정과 부하 테스트를 개선하고 있습니다.

01FEATURES

구현 기능과 현재 상태

실제 저장소의 구현 내용과 진행 중인 기술 과제를 구분했습니다.

AUTHENTICATION

회원 인증과 채팅방 접근 제어

회원가입·로그인·로그아웃에 HTTP Session 인증을 사용합니다. REST 요청과 STOMP 메시지에서 인증 상태 및 채팅방 참여 권한을 확인합니다.

MESSAGING

실시간 송수신과 대화 이력

WebSocket/STOMP로 메시지를 주고받고 MySQL에 저장합니다. 방 진입 시 불러온 과거 이력과 실시간 이벤트를 병합해 도착 순서가 다른 이벤트로 최신 메시지가 가려지는 상황을 줄입니다.

CROSS-INSTANCE

Redis Pub/Sub 중계

두 Spring Boot 인스턴스가 채팅 이벤트를 발행·구독해 서로 다른 인스턴스에 연결된 사용자에게 메시지를 전달합니다. Redis Pub/Sub 자체는 영속 큐나 메시지 순서 보장 계층이 아닙니다.

READ RECEIPTS

메시지별 미읽음 인원 수

사용자별 마지막 읽은 위치를 관리하고 메시지별 미읽음 인원 수를 계산합니다. 읽음 상태 이벤트도 Redis Pub/Sub으로 인스턴스 사이에 전달합니다.

PROFILE & LINKS

닉네임과 URL 표시

사용자는 닉네임을 변경할 수 있으며 메시지에 현재 표시 이름이 반영됩니다. 본문 URL은 클릭 가능한 링크로 표시하고 새 탭으로 열 때 안전 속성을 적용합니다.

LOCAL DEVELOPMENT

로컬 실행 환경 분리

PowerShell 시작·종료 스크립트와 로컬 전용 Compose를 제공합니다. 로컬 MySQL은 호스트 3307 포트를 사용해 Windows MySQL의 3306 포트와 분리합니다.

EC2 MEMORY

모니터링과 연결 풀 비용 조절

Prometheus/Grafana를 선택형 Compose 프로필로 분리했습니다. SQL 표준 출력은 기본 비활성화하고 HikariCP 기본 풀 상한을 인스턴스당 4개로 제한해 작은 EC2의 메모리·연결 예산을 관리합니다.

MEASUREMENT

HTTP와 WebSocket을 별도로 검증

k6 스크립트로 인증, 방 생성·참여, WebSocket 연결, 교차 인스턴스 메시지 전달을 측정합니다. 테스트 데이터가 생성되므로 운영 DB 대신 별도 테스트 환경에서 실행해야 합니다.

OBSERVABILITY

Prometheus + Grafana

Actuator/Micrometer 메트릭을 수집해 HTTP 지연과 JVM 및 프로세스 상태를 관찰할 수 있도록 구성했습니다. 운영 자원 사용량 때문에 필요 시 프로필로 켜는 방식입니다.

측정 해석

이전 5 VU 저부하 실행에서는 HTTP 요청 실패 0%, WebSocket 연결 23/23, 교차 인스턴스 전달 360건·p95 27ms가 기록됐습니다. 이후 2 VU / 60초 / 100ms 간격 테스트는 전달 1,158건·평균 18.96ms·p95 34ms였습니다. 조건이 서로 다르므로 두 결과를 직접적인 개선율로 비교하면 안 됩니다.

04DEPLOYMENT & DEVELOPMENT

로컬 개발과 EC2 배포 흐름

개발 환경과 운영 환경을 분리하고, GitHub Actions에서 테스트·배포 작업을 관리합니다.

LOCAL

PowerShell + Docker Compose

start-local.ps1과 stop-local.ps1로 로컬 실행 환경을 관리합니다. 로컬 전용 MySQL·Redis 포트를 운영 포트와 분리해 개발 PC의 기존 서비스와 충돌을 줄입니다.

CI

Pull Request 검증

.github/workflows/ci.yml은 JDK 21, MySQL, Redis 환경에서 Gradle 테스트를 실행합니다.

EC2 CD

main push 기반 배포

deploy-ec2.yml은 main 푸시 시 self-hosted Windows runner에서 SSH로 EC2에 접속해 저장소를 갱신하고 Compose 서비스를 재배포하도록 구성돼 있습니다. 배포 성공 후에도 실제 로그인과 채팅 동작을 별도로 확인해야 합니다.

MONITORING

필요할 때만 실행

운영 기본 구성은 Nginx, 두 앱 인스턴스, MySQL, Redis 중심입니다. Prometheus와 Grafana는 --profile monitoring으로 별도 실행합니다.

05KNOWN LIMITATIONS

완료한 개선과 아직 해결하지 않은 문제

성능 수치가 좋아졌다고 모든 메시지 전달 조건이 해결된 것은 아닙니다.

OPEN ISSUE

동시 메시지의 방 단위 순서 보장

강한 테스트에서 메시지 순서 역전 6건과 도착 시점 sequence gap 6건이 관측됐습니다. gap은 늦게 도착한 메시지 때문에 생길 수 있어 실제 유실과 구분하는 검증 로직도 추가 확인이 필요합니다.

Redis listener를 단일 스레드로 직렬화한 시도는 성능 회귀가 커서 되돌렸습니다. 현재는 순서 보장이 완료된 것으로 표시하지 않고, DB 저장부터 Redis 발행·수신과 STOMP 전달까지 단계를 나눠 추적하는 것을 다음 과제로 두고 있습니다.

02단계별 지연 추적

DB 저장, Redis 발행/수신, WebSocket 전송 시간을 나눠 확인합니다.
