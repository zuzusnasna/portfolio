06REAL-TIME CHAT / PROJECT DETAIL

서로 다른 서버에 연결된 사용자도
실시간으로 대화할 수 있도록.

WebSocket/STOMP 기반 채팅에 세션 인증과 채팅방 권한 검증을 적용하고, Redis Pub/Sub으로 다중 Spring Boot 인스턴스 간 메시지와 읽음 상태를 중계합니다. 메시지별 미읽음 인원 수를 표시하며 Prometheus·Grafana와 k6로 운영 지표 및 기본 전달 흐름을 확인했습니다.

01PROBLEM & SOLUTION

인스턴스가 달라도 메시지는 전달되어야 합니다.

WebSocket 연결이 서로 다른 앱 인스턴스에 분산되면 한 서버에서 발생한 메시지 이벤트를 다른 서버의 구독자에게 전달할 중간 경로가 필요합니다.

PROBLEM

인스턴스 간 메시지 전달

각 서버는 자신에게 연결된 WebSocket 세션을 관리하므로, 서버 하나의 로컬 처리만으로는 다른 인스턴스에 연결된 사용자를 대상으로 메시지를 전달할 수 없습니다.

SOLUTION

Redis Pub/Sub 브로드캐스트

각 인스턴스가 Redis Pub/Sub 채널을 통해 메시지 이벤트를 발행·구독하도록 구성해 서버 경계를 넘어 메시지 전달 흐름을 연결했습니다.

READ RECEIPTS

메시지별 미읽음 인원 표시

사용자별 마지막 읽은 메시지 위치를 저장하고, 메시지별 미읽음 인원 수를 계산합니다. 읽음 상태 변경은 Redis Pub/Sub으로 다른 인스턴스에도 전달하며 중복 읽음 처리로 인한 카운트 변경을 방지합니다.

OBSERVABILITY

운영 지표를 수집하고 시각화

Spring Boot Actuator/Micrometer 메트릭을 Prometheus가 수집하고, Grafana 대시보드에서 HTTP 요청량, p95 응답 시간, JVM 메모리, CPU 사용량을 관찰할 수 있도록 구성했습니다.

VALIDATION

두 인스턴스 간 메시지 전달 검증

k6 스크립트로 사용자 생성·로그인·채팅방 생성 및 참여, WebSocket 연결과 교차 인스턴스 메시지 수신을 검증했습니다.

CI / CD

main push 기반 로컬 재배포

GitHub Actions가 Windows self-hosted runner에서 Docker Compose 서비스를 빌드하고 컨테이너를 재생성하도록 구성했습니다. EC2 자동 배포는 아직 별도 안정화·검증 항목으로 관리합니다.

04MESSAGE FLOW

메시지 전달과 메트릭 수집

사용자 메시지는 Redis Pub/Sub을 통해 인스턴스 사이를 이동하고, 모니터링 데이터는 별도 scrape 경로로 수집됩니다.

01 · PUBLISH

메시지 발행

클라이언트가 WebSocket/STOMP 연결을 통해 메시지를 발행합니다.

02 · BROADCAST

Redis Pub/Sub

애플리케이션 인스턴스가 채널을 통해 메시지 이벤트를 발행하고 구독 인스턴스에 전달합니다.

03 · DELIVER

WebSocket 구독자 전달

각 인스턴스는 자신에게 연결된 관련 구독자에게 메시지를 전달합니다.

04 · READ STATE

읽음 상태 갱신

채팅방을 열어 메시지를 읽으면 사용자별 읽음 위치를 갱신하고, 미읽음 인원 수를 다시 계산해 화면에 반영합니다.

05 · OBSERVE

Prometheus → Grafana

HTTP, JVM 및 프로세스 지표를 수집하고 대시보드에서 시간 흐름에 따라 관찰합니다.
